# RUNBOOK — راهنمای جامع مدیریت سیستم چند ایجنتی (نسخه ۵.۳)

این مستند نحوه مدیریت چرخه حیات توسعه نرم‌افزار با ایجنت‌های تخصصی را توضیح می‌دهد. در نسخه ۵.۳، تفکیک سلسله‌مراتبی Master به مایل‌استون‌های متعدد و فوق‌العاده دقیق (`1-to-N Granular Milestones`)، مشخصات فنی عمیق قراردادها و ماتریس اعتبارسنجی TDD اضافه و تثبیت شده است.

## ساختار معماری ایجنت‌ها (Multi-Agent Lifecycle)

```
       ┌───────────────────────────────┐
       │   Orchestrator (EXECUTE.md)   │
       │   تخصیص تسک بر اساس مایلستون   │
       └──────────────┬────────────────┘
                      │
        ┌─────────────┴─────────────┐
        ▼                           ▼
┌───────────────┐           ┌───────────────┐
│   Architect   │           │   Developer   │
│ طراحی قرارداد │           │   پیاده‌سازی   │
└───────┬───────┘           └───────┬───────┘
        │                           │
        └─────────────┬─────────────┘
                      ▼
              ┌───────────────┐
              │  QA Engineer  │ ◄───────┐
              │ تست‌نویسی TDD │         │
              └───────┬───────┘         │ Feedback Loop (Max 3)
                      │                 │ (در صورت باگ)
             Pass? ───┼── No ───────────┘
                      │
                     Yes (SUCCESS)
                      ▼
              ┌───────────────┐
              │Security/DevOps│
              │  استقرار و CI │
              └───────────────┘
```

## اصول مهندسی کیت (Non-Negotiable Principles)
1. **اصل تک‌مسئولیتی (SRP):**
   - Developer هرگز تست نمی‌نویسد (جلوگیری از تست جانبدارانه).
   - QA هرگز کدهای بیزنس لاجیک را برای پاس شدن تست‌ها دستکاری نمی‌کند.
   - Orchestrator فقط DAG تسک‌ها را سازمان‌دهی و دیسپچ می‌کند.
2. **قرارداد انتقال ساختاریافته (Strict JSON Handoff):**
   - تمام ارتباطات درون `agent/.state/handoff.json` ذخیره و با `python3 agent/tools/validate_state.py` بررسی می‌شود.
3. **تفکیک سلسله‌مراتبی Master به مایل‌استون‌های ریزدانه (Hierarchical Master-to-Milestones):**
   - مسترها (`agent/masters/NN-*.md`) اسناد معماری کلان (Epic) هستند و وارد کدنویسی ریز نمی‌شوند.
   - هر مستر به **۱ تا ۱۰+ مایل‌استون مجزا و با جزئیات کامل فنی** (`agent/Milestones/NN-MM-*.md`) تجزیه می‌شود. هر مایل‌استون باید شامل قراردادهای دقیق، هندلینگ خطاهای مرزی، و تست‌های TDD باشد ($\le 5$ فایل، ۱ تا ۲ ساعت زمان).
4. **مکانیزم ضد لوپ (Anti-Looping):**
   - چرخه رفت‌وبرگشت بین QA و Developer به ۳ بار محدود شده است (`qa_retry_count`). اگر کد بعد از ۳ بار پاس نشد، وضعیت `BLOCKED` شده و باگ در `Failed-approaches.md` ثبت می‌گردد تا انسان مداخله کند.
5. **ایزولاسیون با Subagents (در پلتفرم‌های پشتیبانی‌کننده):**
   - برای جلوگیری از Context Bloat، ارکستراتور می‌تواند هر نقش را به عنوان یک Subagent مستقل با کانتکست مجزا فراخوانی کند.

## عیب‌یابی و مدیریت وضعیت (Troubleshooting)
- **بررسی سلامت وضعیت:** اجرای `python3 agent/tools/validate_state.py` در هر مرحله.
- **خروج از حالت BLOCKED:** اپراتور انسانی تغییر لازم را اعمال کرده، `feedback_loop.qa_retry_count` را صفر کرده و وضعیت را به `IN_PROGRESS` برمی‌گرداند.
